ScrivenGroup web stack

One-page human brief, then the comparison axes an agent should score. Do not treat planned items as shipped. Versions from package.json / package-lock.json.

Live: app-scrivengroup (Australia East) · Intended domain: scriven.group · Repo package: scrivengroup 0.1.0 (private)

ELI5

ScrivenGroup is one office building, not a street of separate shops.

You enter through a locked front door. On the live site that door is Microsoft work login. On a developer laptop it can be a simple name box. Reception is Home. Four floors: Work, Projects, Internal, and System. Each product is a room on a floor — not its own building with its own paint and keys.

The building is Next.js: it draws the pages you see and does the back-office work (save a file, check a password) in the same program. React is how the pages are assembled. TypeScript is a spell-check so names and shapes stay consistent. Tailwind plus a few house colours (ink, page, surface) keep rooms looking like the same company. The typeface is Manrope.

When you change something, the server usually writes a JSON file into a folder on disk — a labelled folder in a filing cabinet. There is no production database in the app code yet. A Postgres host (Neon) is the planned upgrade; the connection string may already exist on Azure. That is a new records room, not knocking the building down.

The building sits on a rented plot in Australia East: Azure App Service, Linux, Node 20. Developers build on Windows, zip a ready-to-run copy, and upload it. Azure is told not to rebuild on arrival.

One app. One host. Files for now. Microsoft login. No extra UI kit. No second framework.

Metaphor map: building = the Next.js app · floors = /w /p /i /s · rooms = registry nodes · filing cabinet = data/*.json · landlord = Azure App Service · doorman = Auth.js + Entra.

What actually runs

1. Browser

  • HTML from Next App Router (mostly Server Components).
  • Client JS only where "use client" is used.
  • CSS tokens: --ink #3c3c3b, --page #f5f5f4, surface, border, muted, RAG colours. Product hex codes colour badges only unless a ThemeContract exists.
  • Skip link, 44px targets, reduced-motion kill switch.

2. Next.js app (src/)

PathRole
src/app/Routes: /login, /home, /w/*, /p/*, /i/*, /s/*, api/auth/[...nextauth]
src/core/Shell, registry, JSON store, feedback, access RAG
src/modules/Product UI (sunwater-mrt, funds-forecaster, …)
src/auth.tsAuth.js providers
src/auth.config.tsJWT callbacks, authorized gate
src/middleware.tsAuth.js middleware; matcher skips static assets

Mutations use Next Server Actions, not a separate public REST API.

3. Auth gate

Allow /login, /api/auth/*, /w/sunwater-mrt/guest; otherwise require a session. MRT guests may only use /w/sunwater-mrt and children. Guest share expiry lives on the JWT.

Live env: AUTH_SECRET, AUTH_URL, Entra id/secret/issuer, DEV_AUTH=false. Local: DEV_AUTH=true enables Dev Login.

4. Data

JSON files, seed-merge into existing files, Zod schemas where module stores need them. Same types for demo and production so the store can graduate without a rewrite. DATABASE_URL may exist on App Service. No ORM and no Postgres client in source.

5. Build and deploy

npm run build          → next build (standalone)
npm run deploy:prepare → copy .next/standalone + static + public; start = node server.js; linux sharp
npm run deploy:zip     → zip with forward-slash paths (Linux Kudu)
npm run deploy:azure   → az webapp deploy (Entra). SCM Basic Auth stays Off

App Service: SCM_DO_BUILD_DURING_DEPLOYMENT=false, ENABLE_ORYX_BUILD=false, startup node server.js. Dev machine Windows. Host Linux x64. Publish-profile script is legacy.

6. Tooling (dev-time only)

ESLint 9 + eslint-config-next. PostCSS = Tailwind 4 plugin. No Prettier package.

Locked product rules (not stack accidents)

  1. Extend this app only — no second Vite/CRA/Next repo, no parallel design system.
  2. Keep chrome — AppShell, Site network, Feedback, Profile, PageNav.
  3. Registry — Home cards, Site network, Definition maps come from RegistryNode in src/core/registry/seed.ts.
  4. Access — shared | restricted | per_user. Status — sketched | building | live. Sketched = featureless shell + changelog plan, no fake UI.
  5. Work hub is a studio — do not treat /w/ as the client’s production host.
  6. Guest demo is a share link, not a static HTML export of the Next app.
